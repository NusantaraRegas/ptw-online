# OPN-009: Topologi produksi dan high availability

- Status: ACCEPTED
- Owner: TI
- Approver: pemilik produk NR PTW Online (arahan pengguna, sesi 24 September 2026)
- Tanggal keputusan: 24 September 2026
- Berlaku mulai: rilis produksi pertama

## Keputusan yang dibutuhkan

- Platform runtime, network zones, ingress/TLS, dan secret management.
- Availability target, scale, failover, maintenance, dan deployment strategy.
- SQL Server topology, storage, backup, monitoring, serta capacity baseline.
- Ownership operasional, on-call, observability, dan incident response.

## Keputusan

| Topik | Keputusan |
| --- | --- |
| Platform | Satu host Linux dengan Docker Compose (`deploy/compose/compose.prod.yaml`). Bukan HA; pemulihan = restore dari backup. |
| Paparan | Sistem **dapat dijangkau dari internet**. Tidak ada WAF/CDN di depan; nginx adalah edge. |
| Ingress/TLS | TLS berakhir pada container nginx (`nginxinc/nginx-unprivileged`) dengan sertifikat yang disediakan TI pada `PTW_TLS_CERT_DIR`. Port 80 hanya redirect ke host kanonik; host lain ditolak saat handshake; HSTS aktif. **Amendemen 1**: untuk nama publik, TLS berakhir pada reverse proxy korporat `10.10.10.150` yang meneruskan HTTP polos; lihat bagian amendemen. |
| Rate limiting | Diterapkan di nginx (`limit_req` per alamat: umum 30 r/s, login 20 r/menit, statis 100 r/s; `limit_conn` 50). API hanya backstop in-process yang dikunci pada alamat yang diteruskan dari subnet nginx. |
| Secret management | File `.env` pada host deployment (mode 600, di luar Git) adalah penyimpan secret. Tidak ada vault. `.env` dan volume `data-protection-keys` masuk set backup. |
| Database | SQL Server Express (belum ada lisensi). Batas: 10 GB per database, buffer pool ±1,4 GB, 4 core, tanpa SQL Agent/Always On. Port 1433 hanya dipublikasikan pada alamat antarmuka internal (`PTW_SQL_BIND_ADDRESS`) untuk sistem backup melalui network `sql-export` (Docker tidak mempublikasikan port container yang hanya berada di network internal). `sa` hanya untuk migrate/db-init; api/worker memakai login `ptw_app` (`db_datareader`+`db_datawriter`). |
| Backup | Sistem backup internal yang sudah ada menarik database dari server produksi sesuai jadwalnya (login opsional `ptw_backup`). RPO/RTO mengikuti jadwal sistem tersebut; angka eksplisit belum dinyatakan (OPN-008). Volume `attachment-data`, `generated-document-data`, `data-protection-keys`, dan `.env` **wajib ditambahkan** ke tarikan yang sama karena tidak tercakup oleh dump database. |
| Isolasi container | api/worker/web berjalan read-only, `cap_drop ALL`, `no-new-privileges`, batas memori dan pids, log json-file dirotasi. Network `backend` internal; `frontend` bersubnet tetap agar API hanya mempercayai `X-Forwarded-*` dari nginx. |
| Health/admin | `/health/*` hanya dari loopback dan jaringan privat; `/api/v1/admin/*` dapat dibatasi ke CIDR kantor/VPN (`PTW_ADMIN_ALLOW_CIDRS`). |
| Observability/on-call | Belum diputuskan; log container adalah satu-satunya sumber saat ini. |

### Amendemen 1 (25 September 2026, ACCEPTED): TLS publik berakhir pada reverse proxy korporat

Arahan TI: nama publik `ptw.nusantararegas.com` diarahkan DNS internal ke reverse proxy korporat
`10.10.10.150` (nginx bersama untuk aplikasi `*.nusantararegas.com`) yang memegang sertifikat wildcard
dan meneruskan permintaan ke host PTW `10.10.10.121` sebagai **HTTP polos pada port 80**. Pemilik produk
menerima topologi ini pada 25 September 2026.

- nginx PTW tetap memegang sertifikat dan port 443 (akses langsung dan smoke test), tetapi permintaan
  HTTP polos dari sumber yang tercantum pada `PTW_TRUSTED_PROXY_CIDRS` dilayani, bukan dialihkan, bila
  proxy menyatakan `X-Forwarded-Proto: https`. Sumber lain tetap dialihkan ke https (fail-closed), sehingga
  header itu tidak dapat dipalsukan dari LAN.
- `real_ip` hanya mempercayai `X-Forwarded-For` dari proxy tersebut, sehingga rate limit, allow-list
  `/api/v1/admin/` dan `/health/`, jurnal login, dan log akses memakai alamat klien asli, bukan alamat proxy.
- nginx PTW meneruskan `X-Forwarded-For` tunggal (`$remote_addr`) dan `X-Forwarded-Proto` yang sudah
  diselesaikan ke API; API tetap hanya mempercayai header dari subnet `frontend`.
- Risiko diterima: lalu lintas proxy → host PTW berjalan clear text di jaringan internal `10.10.10.0/24`
  (kelas risiko yang sama dengan amendemen OPN-007 untuk Portal API). Kontrol: kedua host berada pada
  subnet internal yang sama; tidak ada hop internet; HSTS dan cookie `Secure` tetap berlaku pada klien.
- Temuan terbuka untuk TI: proxy `10.10.10.150` menyajikan sertifikat wildcard tanpa intermediate Sectigo,
  sehingga klien yang ketat gagal memverifikasi rantai; perbaikan ada di sisi proxy.

## Konsekuensi dan kontrol

- Tanpa lapisan anti-DDoS volumetrik di depan nginx, bandwidth host adalah batas; serangan volumetrik harus ditangani di perimeter jaringan Pertamina.
- Kapasitas Express harus dipantau: tabel audit append-only dan outbox tidak pernah dipangkas.
- Per-IP limiting di belakang NAT kantor: satu alamat mewakili banyak pengguna; nilai zona dipilih longgar untuk itu dan dapat disetel di `deploy/nginx/prod.conf.template`.
- Rollback: `docker compose ... down` tanpa `--volumes`, lalu `up` image sebelumnya; migration bersifat additive.
