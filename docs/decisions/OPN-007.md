## Keputusan yang dibutuhkan

## Keputusan

### Bagian 1: identitas produksi (ACCEPTED)

Login produksi memakai **verifikasi kredensial melalui Portal API** (`POST {PortalAuth:BaseUrl}api/v1/User/SecureAuth`; Portal yang melakukan bind Active Directory Pertamina) **ditambah akun lokal terdaftar**. Tidak ada OIDC/SSO baru sebagai prasyarat go-live.

- Endpoint `POST /api/v1/auth/login` diaktifkan di luar `Development` hanya dengan `Authentication:LoginEnabled=true`. Startup gagal bila nilai itu aktif tanpa `PortalAuth:BaseUrl` ber-skema `https`, sehingga produksi tidak pernah berjalan dengan password lokal saja.
- Portal API hanya membuktikan password. Identitas, role, dan scope tetap berasal dari `UserAccount` aktif dan assignment approved/effective yang dihitung ulang pada setiap request; token JWT Portal dibuang.
- Sesi adalah cookie HTTP-only, `SameSite=Strict`, `Secure` wajib di luar `Development`, umur 8 jam sliding.
- Fallback password lokal saat Portal menolak atau tidak tersedia **dipertahankan** sesuai perilaku yang disetujui. Rekomendasi terbuka: membatasinya ke akun break-glass Administrator; belum diputuskan.
- Break-glass: akun Administrator lokal yang dibuat saat provisioning awal. Maker dan checker assignment wajib berbeda (`AllowAdministratorSelfApproval=false`), sehingga produksi memerlukan minimal dua Administrator.
- Header identitas development (`X-Dev-*`), mode demo, dan OpenAPI tetap tidak tersedia di luar `Development`.
- Login internet-reachable dilindungi rate limit nginx per alamat pada `/api/v1/auth/login` (lihat OPN-009), backstop in-process per alamat, dan lockout akun lokal 5 percobaan/5 menit.

#### Amendemen 24 September 2026: Portal API tanpa TLS di jaringan internal (ACCEPTED)

Portal API produksi hanya tersedia melalui `http://10.10.10.12:7100` di jaringan internal
10.10.10.0/24 dan tidak menyediakan endpoint https. Pemilik produk menerima risiko bahwa kredensial
login transit dalam clear text dari container `api` ke Portal di jaringan internal tersebut.

- Startup tetap fail-closed: `http://` untuk `PortalAuth:BaseUrl` di luar `Development` hanya
  diterima bila `PortalAuth:AllowInsecureHttp` bernilai literal `true` (variabel compose
  `PTW_PORTAL_API_ALLOW_INSECURE_HTTP`). Nilai lain atau tidak ada tetap menggagalkan startup.
- Opt-in ini tidak melonggarkan kontrol lain: cookie sesi tetap `Secure`, TLS publik tetap di nginx,
  dan fallback password lokal tidak berubah.
- Container `api` mencatat warning `InsecurePortalHttpAccepted` pada setiap start selama opt-in aktif.
- Kontrol kompensasi: Portal hanya dapat dijangkau dari jaringan internal; host produksi berada di
  subnet yang sama; tidak ada hop melalui internet.
- Rekomendasi terbuka: TI menyediakan endpoint https untuk Portal API, lalu opt-in dihapus.

### Bagian 2: keterkaitan E-SIMI berbasis bukti (ACCEPTED 25 September 2026)

Keterkaitan E-SIMI pada baseline dibuktikan melalui nomor referensi pada draft dan lampiran berkode
`ESIMI` yang wajib sebelum submit (PTW-WORKFLOW-BASELINE Amendemen 2). Adapter API, verifikasi
terstruktur, dan inbox/outbox integrasi adalah backlog dan bukan prasyarat operasional.

## Konsekuensi dan kontrol

- Kredensial pengguna transit ke Portal lewat TLS; `http://` untuk `PortalAuth:BaseUrl` menggagalkan startup di luar `Development` kecuali opt-in eksplisit `PortalAuth:AllowInsecureHttp=true` sesuai amendemen 24 September 2026 (risiko diterima untuk Portal di jaringan internal).
- Serangan tebak password dari internet dapat memicu lockout Active Directory atas nama staf; kontrol: rate limit login nginx (20 permintaan/menit/alamat, burst 10) dan backstop API (10/menit/alamat).
- Provisioning akun tetap manual oleh Administrator; tidak ada sinkronisasi user dari Portal.
- Hardening 25 September 2026: setiap percobaan login dijurnal append-only (`sec.LoginAuditEvent`: alamat sumber, hasil Portal, jalur identitas, hasil) tanpa password; lockout lokal dijurnal dan dicatat dengan alamat sumber serta tampil pada daftar pengguna; cookie sesi membawa `security_stamp` yang diputar oleh reset password, penonaktifan, dan revoke eksplisit Administrator; password lokal ditolak bila memuat username atau kata umum/nama organisasi (opsional range API Have I Been Pwned, fail-closed); key ring Data Protection wajib terenkripsi sertifikat di luar Development.
- Test: `ProductionModeApiTests` (login fail-closed tanpa konfigurasi, startup gagal tanpa Portal, cookie `Secure` pada login Portal, header dev ditolak, rate limit login); `PortalAuthenticationSettingsTests` (http hanya Development atau dengan opt-in literal `true`; nilai opt-in lain ditolak).
